# ClaudeMap Architecture

## Graph Data Flow

ClaudeMap has one hand-edited graph input:

- `contracts/claudemap-seed-map.json` is the canonical seed map.

Everything else is generated from that seed or from a runtime command:

- `app/public/graph/` is local runtime and Vite staging output. It is generated during development, site builds, and package preparation, and is ignored by git.
- `claudemap-cache.*.json` files are local runtime cache state written by ClaudeMap commands. They are ignored by git because they reflect one machine's last refresh.
- `docs/graph/` is the published website snapshot. These files are generated by the site build and are the only committed generated graph artifacts.
- packaged skills get their runtime graph placeholders during `scripts/package-claudemap-skill.js`; the package output is built from the seed map and should not depend on checked-in `app/public/graph/` files.

## Current Build Paths

`npm run build-site` runs `scripts/generate-seed-map.js`, then `scripts/build-site.js`.
The site build temporarily writes the seed-derived runtime graph, runtime state, and map manifest into `app/public/` so Vite can serve them as static assets. Vite emits the published snapshot into `docs/`, and the temporary `app/public/` files are restored afterward.

`npm run package-skill` runs `scripts/package-claudemap-skill.js`.
The packager copies the app and skill runtime into the artifact, excludes local runtime graph output from `app/public/graph/`, then writes fresh runtime graph placeholders into the packaged skill from the seed map.

## Ownership Rules

- Edit `contracts/claudemap-seed-map.json` for source graph changes.
- Commit `docs/graph/` only when updating the published website snapshot.
- Do not commit `app/public/graph/` or `claudemap-cache.*.json`.
- If graph derivation logic changes, update both site build and skill packaging until a shared generator is extracted.

## Follow-Up

The next architecture step is to extract a shared graph generator, for example `scripts/build-graphs.js`, and call it from the dev workflow, `scripts/build-site.js`, and `scripts/package-claudemap-skill.js`. That would make seed-to-runtime derivation a single implementation instead of two parallel build paths.
